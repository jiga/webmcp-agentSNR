Target: **2:40**, public YouTube, clear narration, no music or third-party logos.

| Time | Picture | Narration / action |
|---:|---|---|
| 0:00–0:12 | Judge landing and readiness signal | “Websites are beginning to expose tools to browser agents. But merchants still cannot see the whole path from agent intent to a real business outcome—or safely improve that tool layer.” |
| 0:12–0:22 | Closed-loop rail; click **Open storefront** | “This is [FINAL NAME], Agent Experience Monitoring running entirely in WordPress. The landing page verifies readiness; the top-level storefront owns the shopper tools and shared state.” |
| 0:22–0:52 | Paste shopper prompt on storefront; visible results, compare, policy, cart | “The storefront registers top-level WebMCP tools from native WordPress Abilities. Controls remain visible separately.” |
| 1:58–2:13 | Capability-gap table and explanation | “Unsupported demand appears beside tool health, so the merchant sees both failures and missing opportunities without calling product views ‘lost revenue.’” |
| 2:13–2:30 | Disable comparison; manifest/tool list changes | “Now I disable comparison for only this demo session. The server blocks it immediately and the browser refreshes the catalog. Another judge is unaffected.” |
| 2:30–2:40 | Repo, ZIP, Docker/Playground artifacts, closing rail | “Any WordPress site can expose safe agent workflows, measure where they succeed or fail, connect them to real outcomes, and improve the experience through WebMCP.” |

## Recording checklist

- Record the exact frozen tag and hosted database state.
- Keep browser zoom high enough to read tool names, evidence, order status, and policy result.
- Show actual calls and visible responses; do not substitute mockups.
- Ensure the timer is below 3:00 after the YouTube upload processes.
- Use original artwork and narration only; no copyrighted music.
- Open all public links logged out before and immediately after publishing.
